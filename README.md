# chat_project_on_go
# ChatApp — текстовый чат для двух клиентов (Go)

##  Цель проекта

Разработать консольное приложение для текстового чата, позволяющее двум пользователям обмениваться сообщениями через центральный сервер. Сервер управляет подключениями, ретранслирует сообщения и обеспечивает корректную обработку разрывов соединений.

## ✨ Возможности

- **Сервер**:
  - Принимает до двух клиентов одновременно (третьему отправляется сообщение об отказе).
  - Пересылает сообщения от одного клиента другому.
  - Обрабатывает отключение клиента и уведомляет оставшегося.
  - Поддерживает команду `SHUTDOWN` для штатного завершения работы сервера.
  - Ведёт логирование в файл `server.log` (время, подключения, отключения, команды).

- **Клиент**:
  - Подключается к серверу по IP-адресу и порту (аргументы командной строки).
  - Отправляет и принимает текстовые сообщения в реальном времени.
  - Поддерживает команды:
    - `EXIT` — завершение работы клиента.
    - `STATS` — вывод статистики (время подключения, количество отправленных и полученных сообщений).
  - Работает в неблокирующем режиме ввода, позволяя одновременно читать сообщения от сервера и вводить текст.
  - Корректно обрабатывает отключение сервера или другого клиента с выводом системного уведомления.

## 🛠 Сборка и запуск

### Требования
- Компилятор с поддержкой 

### Сборка
```bash
git clone https://github.com/evgeney-fullstack/chat_app.git
cd chat_app
mkdir build && cd build

server — серверное приложение

client — клиентское приложение

Запуск
Сервер (по умолчанию порт 1235):

bash
./server [порт]
Клиент (по умолчанию хост 192.168.1.104, порт 1235):

bash
./client [IP-адрес] [порт]
Пример:

bash
./server 8080
./client 127.0.0.1 8080   # в другом терминале
./client 127.0.0.1 8080   # второй клиент
💬 Протокол общения
Сообщения передаются в виде текстовых строк, заканчивающихся символом \n (разделитель).

Системные сообщения сервера:

Chat started. You can send messages. — начало чата.

INFO: Other client disconnected. Chat ended. — другой клиент отключился.

INFO: Server is shutting down. — сервер завершает работу.

ERROR: Server is full (max 2 clients). — попытка третьего подключения.

Клиентские команды:

SHUTDOWN — завершает сервер (отправляется как обычное сообщение).

EXIT — завершает клиент (локальная команда).

STATS — показать статистику (локальная команда).

🧱 Архитектура проекта
Сервер:

Логирование выполняется асинхронно через отдельный класс Logger с блокировкой.

Клиент:

Работает в одном потоке, используя select() для одновременного мониторинга сокета и стандартного ввода.

Ввод организован посимвольно в неблокирующем режиме (fcntl + O_NONBLOCK), что позволяет реагировать на входящие сообщения без задержек.

Статистика (время соединения, счётчики) обновляется атомарно.
